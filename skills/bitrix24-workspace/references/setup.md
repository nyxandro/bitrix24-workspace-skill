# Настройка: входящий вебхук Битрикс24

Скилл работает от имени сотрудника через **входящий вебхук** — секретный адрес доступа к
порталу. Вебхук видит ровно то, что видит этот сотрудник. Адрес — секрет: в чат с ИИ его
не присылают.

## 1. Создать вебхук

1. В Битрикс24: **Разработчикам → Другое → Входящий вебхук**. Если пункта нет — создание
   вебхуков выключено; администратор включает его в **Настройки → Безопасность →
   Интеграции Битрикс24** («Кто может создавать входящие вебхуки»).
2. В блоке «Настройка прав» отметь 12 прав (в скобках — код права):

   | Право в интерфейсе | Код | Для чего |
   |---|---|---|
   | Чат и уведомления | `im` | чаты, личка, уведомления, оргструктура |
   | Задачи | `task` | задачи и их чаты |
   | Рабочие группы | `sonet_group` | участники групп |
   | Социальная сеть | `socialnetwork` | список и карточки групп, проектов, коллаб |
   | Диск | `disk` | файлы |
   | — | `mail` | почта |
   | Календарь | `calendar` | календарь |
   | Пользователи (базовый) | `user_basic` | имена сотрудников |
   | Телефония (совершение звонков) | `call` | ИИ-итоги видеовстреч |
   | Новости | `log` | живая лента |
   | — | `note` | база знаний |
   | Учёт рабочего времени | `timeman` | рабочее время |

   Права «Почтовые сервисы (`mailservice`)», CRM и прочие **не нужны** — не отмечай их.

   ⚠️ Право `call` нужно только для итогов встреч, но по документации оно же открывает
   платные робозвонки. Скилл их не вызывает, однако при утечке адреса вебхука ими можно
   воспользоваться. Не нужны итоги встреч — не давай `call`.
3. Срок действия — по желанию. Когда он истечёт, скилл скажет `APP_B24_AUTH_FAILED` —
   вебхук надо будет перевыпустить.
4. Сохрани и скопируй адрес вида `https://<портал>.bitrix24.ru/rest/<номер>/<код>/`.

Права можно добавлять и снимать и потом: адрес вебхука при этом не меняется.

## 2. Положить адрес на машину

В обычном терминале (не через чат с ИИ):

```bash
bash -c 'mkdir -p ~/.config/bitrix24-workspace && read -rsp "Вставь адрес вебхука: " U && printf "BITRIX24_WORKSPACE_WEBHOOK_URL=%s\n" "$U" > ~/.config/bitrix24-workspace/.env && chmod 600 ~/.config/bitrix24-workspace/.env && echo " готово"'
```

Адрес не появится на экране и не попадёт в историю команд. Файл доступен только тебе.
Команда обёрнута в `bash -c`, чтобы работать и в zsh (оболочка по умолчанию на macOS).

Вместо файла можно задать переменную окружения `BITRIX24_WORKSPACE_WEBHOOK_URL` — она
главнее файла (удобно для серверов и контейнеров). Файл `.env` в текущей папке скилл
**не** читает.

## 3. Проверить

```bash
node <каталог-скилла>/scripts/b24.cjs status
```

Все разделы в `sections` должны быть `ok`, `scopes.extra` — пустым.

## Если адрес утёк

Вставил в чат, закоммитил, отправил кому-то — **удали этот вебхук** в Битрикс24 (он
сразу перестанет работать), создай новый и замени адрес в файле.

## Несколько машин

На каждой машине агента — свой файл `~/.config/bitrix24-workspace/.env` с тем же адресом.
Лучше копировать его безопасным способом (`scp`), а не через мессенджеры и чаты.
